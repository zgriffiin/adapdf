# Adapdf 0.2.0 (pre-release)

Adapdf turns a Word training guide into an accessible PDF (WCAG 2.1 AA and PDF/UA-1)
on your own computer. It has no subscription. This is a pre-release: read "Pre-release:
what is tested and what is not yet confirmed" below before you rely on it.

Version 0.2.0 comes from trying 0.1.0 on a real guide. The big change: **Adapdf never
changes your original guide any more.** It saves the fixes in a copy.

## What changed since 0.1.0

- **Fixes go into an accessible copy.** For `Guide.docx`, Adapdf makes a folder
  `Guide - Adapdf` next to it, with `accessible.docx` (the copy with the fixes),
  `Guide.pdf`, `report.html` and `report.json`. Your original is not changed, and nothing
  else is written next to it. There are no backup files: the original is the backup.
  After the first fix, Adapdf and Word work on the copy.
- **A path that Word cannot open is found early.** Word cannot open a file whose full
  path is longer than 259 characters. If the path of the copy would be longer, a fix and
  **Open in Word** stop with a plain message, and write nothing: move the guide to a
  folder with a shorter path (for example a folder nearer the top of OneDrive). The
  export works in any folder: Word opens a copy of the guide in a short temporary
  folder.
- **If the copy exists**, the app asks: **Continue with the accessible copy** or
  **Start over from the original** (which replaces the copy, including the changes you
  made to it in Word, and asks you to confirm). The command line does the same with
  `--continue` and `--start-over`.
- **Open in Word** opens the copy in your own Word, for the problems that Adapdf
  cannot fix. Adapdf does not control that Word. Make the change, save, then choose
  **Check again**.
- **Title suggestions.** The title field has buttons with texts from your guide (the
  file name, the Title paragraph, the first Heading 1). Nothing is filled in until you
  click one, and you can change it. The field is now visible (it was grey on grey).
- **Every screen says which file it works on and where it is**, with an **Open
  folder** button. After a fix: "Saved your fixes to accessible.docx. Your
  original Guide.docx was not changed."
- **A fix log inside the copy.** Every fix is recorded in the copy (the custom document
  property `Adapdf fix log`): the date and time, the rule, the place, what was done, and
  the text that you typed or chose. The report lists all of them.
- **Findings say where the problem is in Word's words** ("In the page header of
  section 2 (all pages)") and not the name of a file part, and the "how to fix" texts say
  where to click in Word.
- **Table headers get a scope.** Word writes the first row and the first column of a
  table as header cells but never writes a scope for them, and veraPDF fails that.
  Adapdf adds the scope to the PDF after the export and lists it in the report. A first
  row counts as column headings only when every cell in it is a header cell; otherwise
  the header cells of the first column get the scope Row.
- **Merged or split cells in a table (TBL-003) are now an error.** Word's PDF of such a
  table fails PDF/UA-1 7.2-42, so the export waits until the cells are split or the
  table is made text.
- **A clearer report.** The Word document check and the PDF check are shown apart. The
  place of a veraPDF failure is given in words ("Table 1, body row 1, cell 2"). The HTML
  report has no form fields (a page with no script cannot save them): record the PAC
  result, the PAC report file and the sign-off in the app, and the page shows them.

Adapdf does not send your documents anywhere. It works on your computer. Its window
turns off WebView2's background services (WebView2 is the Microsoft component that draws
the window). See the test plan for what was observed; the check samples the connections
about once a second and is not a firewall log.

## Download

Download `Adapdf_0.2.0_x64-setup.exe` from the assets of this release.

The SHA-256 of the file is in `SHA256SUMS.txt`, also in the assets of this release.
To check it, run `Get-FileHash .\Adapdf_0.2.0_x64-setup.exe -Algorithm SHA256` in
PowerShell and compare the value.

The release also has `OpenJDK21U-jdk-sources_21.0.13_9.tar.gz`: the source code of the
Java runtime that the installer includes (its licence, GPLv2, asks for it). You do not
need it to use Adapdf.

The [install guide](https://github.com/zgriffiin/adapdf/blob/v0.2.0/docs/install-guide.md)
tells you how to install and use it. You need no admin rights.

## What you need

- Windows 11, 64-bit.
- Microsoft 365 Word, installed on the computer.
- About 250 MB of free disk space.
- You do not need to install Java or any other program.

## Pre-release: what is tested and what is not yet confirmed

Tested:

- The checks, the fixes, the copy and its log, the Word export, the PDF metadata step,
  the veraPDF run, the report and the app have automated tests, and were run with a
  real Word and a real veraPDF on made-up test guides. A test opens the fixed copy in
  Word, saves it under a new name, reads the fix log back, and adds a new fix to the
  file that Word wrote.
- One real training guide (the guide whose 0.1.0 export failed veraPDF rule 7.5-1) was
  exported with a 0.2.0 development build on 2026-11-18: the verdict is Pass, with 0
  errors and 3 warnings in the pre-check and 0 failed veraPDF rules; the table header
  cells got their scopes. A temporary copy was used, and PAC was not run on it.
- This exact installer file was run on one computer: a silent install, an upgrade over
  version 0.1.0 (one entry in Windows' list of apps, version 0.2.0), a check and an export from
  the installed copy, the accessibility check of the app window, and an uninstall.

Not yet confirmed:

- **PAC has not been run on real guides.** PAC is the checker of record. veraPDF
  passes are not a PAC pass. The first test with 5 real guides (Phase 0 in the
  [product spec](https://github.com/zgriffiin/adapdf/blob/v0.2.0/docs/specs/01-product.md))
  is still to do.
- **The screen-reader walkthrough of the app is not done.** The pages pass automatic
  accessibility checks (axe-core, also with the colour contrast rule in the real window),
  but a person has not yet used the app with a screen reader, high contrast or a
  magnified window.
- **Open in Word has been tried with the opener only in tests that do not start Word.**
  The check that only the copy is opened is tested; a person has not yet clicked it on a
  computer with Word and watched it open.
- **The fix log survives a save in Word 16.0 (Microsoft 365) on the test computer.** It
  has not been tried with other Word builds, or with a document that is saved in a
  shared or synchronised folder.
- **Reports from 0.1.0 do not open in 0.2.0** (the report layout changed to version 3).
  The app says that the report is from an older version. Export the guide again.
- **The install guide has not been tried by a staff user.** A person who did not build
  Adapdf has not yet followed it.
- **One computer, one administrator account.** The installer was not tried on a clean
  computer, on a standard user account, with the city's IT rules (for example
  AppLocker), as an upgrade from 0.1.0, or while the app was running.
- **The installer is not signed.** Windows SmartScreen shows "Windows protected your
  PC". If you got the file from the release page of this project, click **More info**,
  then **Run anyway**.

Details are in the [test plan](https://github.com/zgriffiin/adapdf/blob/v0.2.0/docs/test-plan.md).
